# Submission

## failed_boundary

The provider-transfer boundary succeeded; the failure was the subsequent local SQLite ledger confirmation, specifically `SqliteLedger.confirm`'s final `UPDATE payments SET transfer_id = ...` (app/adapters.py:63-79). `pay` deliberately calls the provider first and confirms afterward (app/core.py:47-54). The exception was `sqlite3.IntegrityError: database or disk is full`, as shown by incident/stderr.txt and the failed confirm trace. Thus this was a post-provider, pre-local-receipt-commit failure, not a provider rejection or request-construction failure.
